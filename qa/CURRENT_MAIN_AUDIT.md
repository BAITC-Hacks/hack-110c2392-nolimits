Проверенная версия `main`: **`ef3ffcd1b480d01b7ae7e0890fcae55d99c3d278`** (23.09.2026, 14:24 UTC+5). Проверка выполнена в отдельном Git worktree `project-current` с помощью QA-набора и тестов команды. Этот SHA повторно сверили с `origin/main` после проверки; новых коммитов на тот момент не было.

Тест A17 русских колонок проходит, если предварительно загрузить новый склад. Первое падение A17 было связано с порядком импорта, а не с распознаванием русских заголовков; вывод в [первом отчёте](BASELINE.md) устарел для этого SHA.

## Проверка на включённой книге EKT

`backend/data/ekt_sales_and_stock_history.xlsx` прочитан целиком: 18 861 продажа, 54 пары товар/склад, 21 строка положительного inbound, 27 строк поставщиков, 3 периода дефицита. Из них рассчитано 54 рекомендации, 10 положительных заказов, 5 поставщиков с положительными заказами, исходный бюджет 3 509 150 ₸. Обнаружено 59 выбросов и суммарно 112,5 ед. оценённого упущенного спроса. Значения воспроизведены вызовом `parse_workbook` и `calculate_recommendations` на этом SHA.

- `EKT-AUT-001`: для склада Астаны заявлен stockout **10–25.06.2026**; оценённый потерянный спрос по этому товару получился **0**, поскольку дни без продаж отсутствуют в таблице. Это наглядный провал Must Have №3 на данных партнёра.
- `EKT-AUT-006` измеряется в **штуках**, но рекомендуемый заказ равен **25,81 шт** для Астаны и **5,69 шт** для Алматы при Pack=1. Числа должны быть целыми; тест E05 ловит тот же дефект на маленьком наборе.
- В файле продаж нет заявленной покупки **4800 м** и клиента `CLNT-VIP-BIG-PROJECT`; максимум одной транзакции `EKT-CBL-002` — **611 м**. README и спецификация набора обещают сценарий, которого нет в файле. Поэтому 59 обнаруженных моделью выбросов не подтверждают именно обещанный кейс на 4800 м.
