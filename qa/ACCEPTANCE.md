# Ручная приёмка перед Hard Freeze

Записать SHA, дату расчёта, версии Docker/браузера и результат каждого пункта: не проверено / пройдено / не пройдено. Все пункты этого документа первоначально **не проверены в запущенном конечном продукте**. Наблюдение в исходном коде не заменяет UI-проверку. Выполнять только на отдельном тестовом экземпляре, особенно перезапуски, ошибочные импорты и тесты гонок.

## Порядок перед сдачей

1. Зафиксировать согласованный SHA; получить его через `git fetch` и `git pull --ff-only` в чистой тестовой копии.
2. Прогнать `qa/run.py`. Разобрать каждое падение; не менять ожидания только ради зелёного отчёта.
3. В первую очередь пройти M01–M05, M09–M12, D01–D03 и обязательные бизнес-сценарии B01, B05, B07, B15, B21.
4. Исправления вносит ответственный разработчик. После нового SHA повторить затронутые сценарии, затем полный короткий прогон.
5. Перед 18:00 сохранить SHA, отчёт, команды воспроизведения и известные ограничения. После Hard Freeze не менять код.
