# Приёмка будущего редизайна

Это checklist требований, не отчёт об их выполнении. Фактические проверки текущего пакета находятся в VERIFICATION.md.

## Основные сценарии

- [ ] Первый запуск без данных ведёт к загрузке; не показывает случайные demo-числа как реальные.
- [ ] Поиск SKU, склад, поставщик, категория и риск комбинируются; сброс возвращает весь набор.
- [ ] Фильтр без результатов отличается от отсутствия данных и ошибки запроса.
- [ ] Нулевые заказы не считаются ошибкой; количество неизвестной единицы не суммируется с известной.
- [ ] Бюджет 0 показан как 0, неизвестная цена как неизвестная; неполный итог подписан.
- [ ] При открытии позиции видны SKU и склад; поздний ответ другой позиции не подменяет график.
- [ ] Расчёт, график, список и экспорт относятся к одному запуску.
- [ ] Пустое/отрицательное/нечисловое количество отклоняется; шаг зависит от единицы и упаковки.
- [ ] Ошибка сохранения сохраняет пользовательский ввод; повтор не дублирует действие.
- [ ] Несохранённая правка не утверждается незаметно; закрытие требует решения о черновике.
- [ ] Конфликт второго редактора показывается явно, чужая запись не перезаписывается.
- [ ] Импорт всех пяти типов и общей книги сохраняет текущую функциональность.
- [ ] Preview импорта действительно не меняет БД; если preview API нет, интерфейс этого не обещает.
- [ ] Ошибки строк доступны после исчезновения toast и содержат поле/причину.
- [ ] Экспорт соответствует выбранной области; до scoped API честно экспортирует всё.
- [ ] Утверждение, экспорт и отправка — разные действия и состояния.
- [ ] Встроенный тестовый набор обозначен синтетическим независимо от названий брендов.

## Визуальное качество и адаптивность

| Viewport | Проверить |
|---|---|
| 1440×900, 1920×1080 | Рабочая таблица на первом экране, минимум 4 строки при 1440×900; длина строк текста не растягивается бесконечно |
| 1366×768 | Минимум 3 рабочие строки, основные действия доступны |
| 1024×768, 768×1024 | Меню и фильтры не сжимают содержание; допустим локальный скролл таблицы |
| 720×900, 390×844, 320×844 | Нет горизонтального скролла страницы; карточки читаемы; диалог помещается |
| 200% zoom / 320 CSS px reflow | Текст и контролы не перекрываются, табличная область прокручивается отдельно |

- [ ] Длинные SKU/имена поставщиков/причины не выходят за карточку.
- [ ] Суммы до 999 999 999,99 ₸ и количество с дробями не обрезаются.
- [ ] Safe areas и экранная клавиатура не скрывают активное поле/действия.
- [ ] Sticky toolbar не перекрывает фокус; последние строки видны над закреплённой панелью.
- [ ] Риск читается без цвета; нет бликов, огромных теней и декоративных графиков без смысла.
- [ ] Все цвета из токенов; произвольные local-hex обоснованы в review.

## Доступность

Цель — WCAG 2.2 AA; это не заявление сертификации. [Критерии W3C](https://www.w3.org/WAI/WCAG22/quickref/).

- [ ] Обычный текст контраст ≥4,5:1; крупный ≥3:1; важные границы/фокус ≥3:1 к соседнему фону.
- [ ] Полный основной сценарий выполняется Tab/Shift+Tab/Enter/Space/Escape.
- [ ] Есть skip link, один h1, логическая иерархия заголовков и landmarks.
- [ ] Все поля и icon-only кнопки имеют доступное имя; errors связаны с полем.
- [ ] В modal фокус ограничен, после закрытия возвращён; фон недоступен.
- [ ] Активная навигация обозначена aria-current, сортировка aria-sort, выбор mixed.
- [ ] Не дублируются скрытая мобильная/desktop версии для скринридера.
- [ ] График имеет описание и доступную таблицу; отсутствие данных не нарисовано нулём.
- [ ] Reduced motion отключает необязательное движение; нет автоисчезающей единственной ошибки.
- [ ] Минимальная цель touch 44 px по внутреннему стандарту команды; проверить исключения отдельно.
- [ ] Ручной проход NVDA/VoiceOver на целевых устройствах, а не только automated axe.

## Скорость и масштаб

Тестовые наборы: 100, 3 000, 10 000 позиций, длинные строки, 20 поставщиков, смешанные единицы, частично отсутствующие цены. Цели для выбранного тестового устройства: видимая реакция локального фильтра ≤150 ms; отсутствие задач UI >200 ms при обычной работе. Это цели, не измеренный результат. Зафиксировать устройство, browser, network и p95. Для больших наборов использовать серверную пагинацию или обоснованную виртуализацию без потери доступности.

## Release gate

Нельзя принимать экран только по happy path. Для каждого screen ID нужны: успешное состояние, загрузка, пустота, ошибка, длинный текст, mobile, keyboard. Отсутствующие API и непроверенные устройства перечислены в release notes. UI и расчётные изменения проходят отдельные проверки. Никаких пометок «готово», если есть только локальный mock.
