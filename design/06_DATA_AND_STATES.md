# Данные, состояния и правила достоверности

## Текущее API → новый интерфейс

| Источник | Использование | Ограничение |
|---|---|---|
| Recommendation.id, sku, warehouse | Идентичность строки | Не использовать индекс; история запусков отсутствует |
| product_name, category, supplier_id/name | Названия и фильтры | Пустое имя не заменять вымышленным |
| current_stock, in_transit, inventory_position | Остаток/транзит/позиция запаса | Текущий расчёт не ограничивает весь транзит сроком прибытия |
| forecast_lead_time, safety_stock, raw_recommended_quantity | След расчёта | Значения с сервера, не независимая UI-модель |
| recommended_quantity, final_quantity | Алгоритм vs решение | Показывать разницу при ручной правке |
| unit_cost, total_cost_kzt | Цена и бюджет | Nullable; валюта KZT; единицы не определены контрактом |
| lead_time_days, days_of_cover, urgency | Покрытие и риск | Риск не равен статусу согласования |
| status DRAFT/ADJUSTED/APPROVED | Статус решения | Не означает отправку поставщику |
| trend_direction/percent, seasonality_detected | Объяснение модели | Не выдавать признак сезонности за точность прогноза |
| outliers_removed, estimated_lost_demand | Влияние обработки | Исходные продажи не удалять из объяснения |
| explanation, metadata | Дополнительная трассировка | Текст как текст, не исполняемый HTML |
| Point actual_sales/adjusted_demand/forecast/date | График | Отсутствие значения — разрыв, не ноль |

Существуют GET рекомендаций/аналитики/выбросов, загрузка данных, demo/load-ekt, calculate, adjust/approve, экспорт. Точные пути брать из `frontend/src/api.ts` текущей ветки перед реализацией. Это документ требований, не автоматически действующий API-контракт.

## Предлагаемые расширения [API]

```ts
type SourceContext = {
  datasetId: string;
  origin: 'uploaded' | 'synthetic' | 'integration';
  asOf: string | null;         // ISO timestamp, timezone included
  importedAt: string | null;
  sourceNames: string[];
};
type CalculationContext = {
  runId: string;
  calculatedAt: string;
  source: SourceContext;
  policyVersion: string;
  modelVersion: string;
};
type DecisionVersion = {
  version: number;
  updatedAt: string;
  updatedBy: string;
  reason: string | null;
};
type QualityIssue = {
  code: string;
  severity: 'warning' | 'blocking';
  field: string | null;
  message: string;
  affectedIds: string[];
};
```

Дополнительно нужны unit, quantityPrecision, packageMultiple, MOQ, currency, arrivalDate/eligibleTransit, qualityIssues, permissions. Ответ списка должен определять scopeSummary, totalCount и cursor/page. Числа JSON могут быть decimal-строками по согласованному контракту — не решать денежную точность случайно в UI. Импорт: previewToken + summary/issues, затем commitToken; оба с TTL и привязкой к исходному файлу. Экспорт: runId + selectedIds/filterSnapshot + format. Изменение: id + expectedVersion + finalQuantity + reason. Сервер сверяет версии и права; конфликт 409 возвращает актуальную запись.

Не добавлять эти поля в mock и объявлять backend готовым. До расширения использовать честное ограничение или скрывать функцию.

## Числа и расчёт

Демонстрационный пример для проверки композиции: спрос 120 шт., страховой запас 20 шт., остаток 35 шт., учитываемый транзит 40 шт. Чистая потребность 120 + 20 − 35 − 40 = 65. MOQ 20, кратность 10 → 70 шт. При цене 1 850 ₸ сумма 129 500 ₸. Ручное решение 80 → 148 000 ₸. Это пример, не новый алгоритм для production.

Если потребность ≤0, рекомендация 0; MOQ не должен создавать заказ без потребности. Учитываемый транзит, резервы и отрицательные остатки требуют согласованной политики. Не называть `current_stock` свободным остатком, если резервы не вычтены. Прогноз и покрытие могут иметь дроби; отображение округлено, исходная точность остаётся в расчёте. Денежный итог брать из серверного подтверждённого результата.

Локаль первой версии ru-RU, валюта KZT. Даты на экране «23 сент. 2026, 14:30», в экспорте однозначный ISO. Часовой пояс организации должен быть настройкой; не брать браузерный как бизнес-истину. В прототипе фиксированная дата вымышленного среза. Единицы показывать рядом с каждым количеством, суммировать только одинаковые единицы. При неизвестной единице «ед. не указана», а не автоматически «шт.».

## Матрица состояний

| Состояние | Отображение | Действия |
|---|---|---|
| Первая загрузка | Skeleton структуры + «Загружаем рекомендации» | Чтение и изменения пока недоступны |
| Повторная загрузка | Старые данные + «Обновляем…» | Не создавать дубликаты операций |
| Нет входных данных | «Добавьте данные для первого расчёта» | Перейти в данные |
| Пустой фильтр | «По этим условиям позиций нет» | Сбросить фильтры |
| Всё обеспечено | «Закупка сейчас не требуется» | Просмотреть нулевые позиции |
| Ошибка без кэша | Постоянный alert, конкретная причина | Повторить; загрузить источники при их нехватке |
| Ошибка с кэшем | «Не удалось обновить. Показан предыдущий результат» | Повторить; изменения по старой версии блокируются |
| Частичные данные | Перечень пропусков и влияние | Исправить источник; доступные строки остаются читаемыми |
| Цена = 0 | «0 ₸» + при необходимости проверка бесплатной цены | По правилам данных |
| Цена неизвестна | «Нет цены», бюджет частичный | Не утверждать как полный бюджет |
| Нет истории спроса | «Недостаточно истории» | Не рисовать плоский достоверный прогноз |
| Расчёт идёт | Этап/время, если есть API; иначе неопределённый progress | Не выдумывать проценты |
| Запись сохраняется | Поле и кнопка заняты, остальные строки доступны | Запрос один; результат подтверждает сервер |
| Сохранение упало | Правка остаётся, inline ошибка | Повторить без потери ввода |
| Конфликт 409 | Актуальное значение рядом с черновиком пользователя | Пересмотреть и отправить новую версию |
| Нет прав | Читать можно по доступу, действие с объяснением | Не считать скрытую кнопку авторизацией |
| Экспорт готов | «Файл подготовлен» | Скачать; не писать «Заказ отправлен» |

## Достоверность и конкурентная работа

Качество данных измеряется проверками, качество прогноза — ретроспективной валидацией; не смешивать. Зелёная галочка загрузки означает только успешный приём, не правильность каждого бизнес-значения. Свежесть требует timestamp источника. Отсутствие stockout-файла не доказывает отсутствие дефицита.

Смена SKU очищает прежнюю аналитику; AbortController или проверка requestId защищает от гонки ответов. При изменении набора отменить запросы старого dataset/run. После сохранения серверный объект заменяет локальный, затем обновляются итоги. Оптимистическое утверждение без подтверждения запрещено. Если второй пользователь изменил строку, нельзя молча перезаписать его решение. localStorage допустим для плотности/фильтров, но не является общей историей или хранилищем утверждений.
