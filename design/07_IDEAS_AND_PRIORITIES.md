# Предложения и приоритеты

Оценки сложности относительные: S — один небольшой UI-блок; M — несколько компонентов/контрактов; L — сквозная функция с хранением и проверкой. Это не обещания сроков. P0 — до демонстрации нового интерфейса; P1 — полноценный рабочий процесс; P2 — развитие после проверки с закупщиками.

| Приоритет | Предложение | Польза | Сложность / зависимость | Проверка успеха |
|---|---|---|---|---|
| P0 | Убрать hero, поставить рабочий список в центр | Быстрее добраться до решения | M / UI | 4 строки при 1440×900 |
| P0 | Честное происхождение данных и дата среза | Пользователь понимает, чему доверяет | M / API для timestamps | Синтетика не названа реальной |
| P0 | Один язык и словарь | Меньше неоднозначностей | S / UI | Нет случайного смешения терминов |
| P0 | Разделить риск/решение/качество | Не перепутать дефицит и ошибку | M / часть API | Три независимых состояния |
| P0 | Исправить null/0 и смешанные единицы | Правильное прочтение бюджета | M / unit API | Неизвестное не складывается как 0 |

## Что удалить или объединить

- Декоративную орбиту и большой вводный слоган убрать с рабочего плана; допускаются на публичной странице продукта.
- Семь равноправных KPI заменить четырьмя действиями/показателями. Технические показатели обработки переместить в объяснение и качество данных.
- Дублирующие карточки поставщиков ниже длинной таблицы заменить режимом группировки того же списка. Один фильтр и один источник итогов.
- Demo-кнопки убрать из постоянной рабочей шапки; оставить в разделе данных с понятным подтверждением замены.
- Фиктивный «Engine online / Live data» заменить реальным статусом запроса и среза. Backend доступен и данные свежие — разные факты.
- Не добавлять общий AI-чат до появления конкретной задачи, проверяемого источника ответа и правил действий. Объяснение закупки в контексте полезнее пустого поля «Спросите AI».
- Не рисовать рейтинг точности, экономию денег и проценты улучшения без измерений. Вместо них показывать наблюдаемые величины.

## Продуктовые эксперименты

Провести 3–5 коротких сессий с реальными закупщиками: найти наиболее срочную позицию, объяснить количество, исправить ошибку источника, выгрузить нужного поставщика. Замерять время, ошибки, места остановки и понимание статуса. Успех — самостоятельное завершение сценария, а не оценка «красиво». Выбор плотности, терминов и места фильтров корректировать по результатам. Не выдавать предположения этого документа за проведённое исследование.
