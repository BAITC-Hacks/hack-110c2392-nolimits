# StockPilot — спецификация полного редизайна

> Актуальное направление: [Classic Professional Dashboard](CLASSIC_DASHBOARD.md). Последнее задание пользователя заменяет прежнюю выразительную лаймовую стилистику. Рабочая реализация находится в React `frontend/src/`, старый HTML-прототип — историческое предложение.

Версия 1.1 · 23.09.2026 · база первичного аудита `402426a`; пакет публикации основан на `a3b3d00`.

Опубликовано как предложение: текущий код команды имеет приоритет над историческими замечаниями аудита. Мобильные исправления и локальные изменения приложения в этот пакет не включены.

**Назначение:** единая опора для дизайнеров, разработчиков и ИИ, которые будут полностью обновлять StockPilot. Пакет содержит продуктовые решения, макет, правила компонентов, поведение в ошибочных состояниях и критерии приёмки. Это проект нового интерфейса, а не описание уже реализованного продукта.

**Направление по прямому пожеланию пользователя:** вернуть зелёную стилистику прежнего интерфейса, сделать её выразительнее. Тёмная лесная навигация, лаймовые акценты, тёплые светлые поверхности, читаемая типографика. Сине-белый вариант отвергнут. Утверждено направление цвета, а не каждый экран или финальный макет.

## Быстрый старт для следующего ИИ

1. Прочитать этот файл, `01_PRODUCT_AUDIT.md` и `02_INFORMATION_ARCHITECTURE.md`.
2. Открыть `prototype/index.html` в браузере. Прототип работает без сборки, API, внешних шрифтов и сети; все его данные вымышлены.
3. Для выбранного экрана прочитать `04_SCREEN_SPECIFICATIONS.md`, затем `05_COMPONENTS.md` и `06_DATA_AND_STATES.md`.
4. Взять значения из `tokens/tokens.json` и `tokens/tokens.css`. Не подбирать новые цвета и размеры по отдельности.
5. Согласовать владельца файлов с двумя другими участниками. Выполнять миграцию по `08_IMPLEMENTATION.md`.
6. Проверить результат по `09_ACCEPTANCE.md`. Не заявлять о завершении недоступных серверных функций на основании макета.

## Как разрешать расхождения

Текущая инструкция пользователя имеет приоритет. Затем: согласованный контракт данных → продуктовые правила `06_DATA_AND_STATES.md` → спецификация экрана → компоненты и токены → визуальный прототип. Прототип иллюстрирует направление и часть сценариев; он не заменяет полный контракт и не задаёт производственный алгоритм закупки. В спорной ситуации занести решение в `DECISIONS.md` и сохранить причину.

Теги требований: **[СЕЙЧАС]** — есть в проверенном коде; **[UI]** — можно построить на существующих данных; **[API]** — нужны изменения backend; **[ИДЕЯ]** — необязательное расширение; **[ДОПУЩЕНИЕ]** — требует согласования. Не смешивать эти статусы в отчёте о готовности.

## Обязательные принципы

- Рабочая таблица и причины действий появляются на первом экране, без рекламного hero-блока.
- Происхождение данных и дата их среза видны всегда. Встроенный отраслевой набор в `backend/data/README_DATASET.md` описан как синтетический — не называть его реальной выгрузкой.
- Риск дефицита, статус заказа и качество данных — три разные характеристики.
- Не складывать метры, штуки и упаковки в «всего единиц». Неизвестная стоимость не равна нулевой.
- Обоснование показывает расчёт и источник, а не придуманный AI-текст или процент уверенности.
- Реальное утверждение работает только с серверным подтверждением, правами и актуальной версией; экспорт не означает отправку.
- Ошибки и нехватка данных остаются видимыми. Красивое состояние не должно маскировать невозможность расчёта.
- Русский — основной язык первой версии; вся терминология единообразна.
- Существующие загрузка, фильтры, аналитика, правка, утверждение и экспорт сохраняются при миграции.

## Просмотр прототипа

Открыть `prototype/index.html` напрямую либо запустить из этой папки `python -m http.server 5174 --bind 127.0.0.1` и открыть `/prototype/`. Прототип не обращается к StockPilot API и не изменяет рабочие заказы. Можно переключать разделы, фильтровать позиции, открывать карточку, менять количество, выбирать строки и проходить макет проверки импорта. Контролы, показывающие будущий функционал, объясняют своё ограничение.

Не копировать `prototype/app.js` в продукт целиком: в нём намеренно упрощённые локальные состояния. Переносить компоненты, композицию и правила в существующий React-проект.
