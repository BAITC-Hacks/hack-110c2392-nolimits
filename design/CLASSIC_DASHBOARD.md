# Classic Professional Dashboard

Актуальное задание пользователя от 23.09.2026. Эта спецификация заменяет прежнюю лаймовую стилистику и HTML-прототип. Реализация находится в существующем React frontend; API и расчётная логика backend не изменяются.

## Визуальная система

Фон #F6F7F9, белые панели, навигация #17211B, основной зелёный #2F6B4F, hover #25563F, мягкий акцент #EAF3EE. Текст #1F2937, вторичный #667085, границы #E2E6EA. Красный обозначает риск/ошибку, янтарный — высокий приоритет. Синий используется только для статуса изменения.

Системный стек Inter / Segoe UI / Arial / sans-serif, без внешней загрузки шрифтов. Основной текст 14px, таблицы 13px, подписи не меньше 12px. Скругления 6px для контролов, 8–10px для панелей. Тени только у модальных окон и drawer.

## Адаптация без горизонтальной прокрутки

- Sidebar 232px на desktop, 72px на tablet, модальное меню на mobile.
- Все grid-колонки допускают сжатие через minmax(0, 1fr), длинные строки переносятся.
- Таблица закупок переходит в подписанные карточки при ширине контейнера до 1050px. Решение зависит от ширины панели, включая разделённое окно и DevTools.
- Таблицы редактора и исключений переходят в карточки при ширине контейнера до 850px.
- Вкладки, фильтры и действия переносятся; шрифт ради вмещения не уменьшается.
- Не исправлять переполнение глобальным overflow-x:hidden: данные должны оставаться доступными.
- У таблицы desktop есть только вертикальная прокрутка и закреплённая шапка. Пагинация рекомендаций — 25 позиций.

## Реальная функциональность и ограничения

Поиск и фильтры склада, поставщика, категории, приоритета, статуса; сортировка; группировка по поставщикам. Существующие импорт CSV/Excel, редактор, черновики и экспорт сохранены. Карточка товара показывает расчёт, график, сезонность, тренд, исключения и восстановленный спрос. Сохранение количества и утверждение используют прежние API.

Причина изменения явно недоступна: API не сохраняет комментарии. История показывает только изменённые и утверждённые позиции текущего расчёта, без выдуманных дат или архива. Политики ведут к реальному справочнику поставщиков. Экспорт явно охватывает весь расчёт, независимо от фильтров.

Не переводить названия товаров, SKU и объяснения backend посредством автоматической подмены в DOM. Интерфейс русский, исходные данные показываются как получены.

## Проверка

На отдельном локальном backend с демонстрационной SQLite-базой проверены поиск, фильтр склада, открытие аналитики, изменение 30 → 35, блокировка утверждения несохранённого количества, сохранение и утверждение. Исходная рабочая база не использовалась для тестовых изменений.

Проверены ширины 1920, 1440, 1366, 1024, 768 и 390: план закупок, данные, исключения, история, политики. DOM-проверка видимых элементов приложения не выявила горизонтального переполнения. На 390 дополнительно проверены все шесть вкладок редактора, раскрытые фильтры и карточка товара.

TypeScript и production build обязательны перед публикацией. Библиотека графиков даёт предупреждение Vite о крупном chunk; это не ошибка сборки.
