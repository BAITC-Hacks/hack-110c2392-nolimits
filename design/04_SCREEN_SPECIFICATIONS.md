# Спецификации экранов

Статусы требований определены в README. Размеры — CSS px. Цель первой версии: закупщик видит проблему, проверяет причину, меняет решение и получает проверяемый файл заказа. Не строить отдельный дашборд ради дашборда.

## S01 · План закупок · /procurement

**Вход:** после запуска, пересчёта, возврата из карточки. **Выход:** карточка позиции, исправление источника, экспорт. Заголовок «План закупок», описание «Проверьте приоритетные позиции и подготовьте заказы поставщикам».

Порядок сверху вниз:

1. Контекст: организация/склад, происхождение набора, дата среза, последний успешный расчёт. Пока API не отдаёт время: «Время расчёта не передано», а не текущие часы браузера.
2. Заголовок и действия «Пересчитать», «Проверить и экспортировать». На телефоне действия переносятся ниже заголовка.
3. Четыре показателя: позиций к закупке, критических позиций, бюджет известных цен, позиций с неполными данными. До появления quality API последний показатель заменяется фактически доступным, например числом поставщиков; не придумывать полноту.
4. Предупреждение только если требует действия: «Для 3 позиций нет цены. Итог бюджета неполный». Ссылка открывает соответствующий фильтр.
5. Быстрые фильтры: все / критические / требуют проверки. Числа вычислены из того же набора, что список. Риск и статус решения фильтруются отдельно.
6. Панель поиска, склада, поставщика, категории, сортировки. На телефоне поиск виден, остальные поля раскрываются кнопкой «Фильтры · N». Показать активные фильтры с удалением каждого и «Сбросить».
7. Таблица или мобильные карточки, затем постраничная навигация. [UI] начать с 25/50/100 строк. [API] перейти к серверной пагинации при росте объёма.

### Колонки и приоритет

| Колонка | Содержание | Ширина desktop | Телефон |
|---|---|---:|---|
| Выбор | Checkbox с названием позиции | 44 | В шапке карточки |
| Позиция | Название, SKU, склад; название открывает карточку | от 240 | Всегда |
| Приоритет | Текст и цвет риска | 120 | Всегда |
| Поставщик | Имя, срок поставки | 160 | Второй уровень |
| Запас | Остаток и отдельно в пути | 130 | В раскрытии |
| Заказать | Итог + единица; подпись о ручной правке | 120 | Всегда |
| Стоимость | Сумма + валюта или «Нет цены» | 140 | Всегда |
| Решение | Черновик / изменено / утверждено | 120 | Всегда |

На 1024–1439 скрывать второстепенную колонку поставщика с сохранением в карточке. Не уменьшать шрифт до 9 px, чтобы впихнуть всё. На широком экране таблица может иметь собственную горизонтальную прокрутку. На телефоне по умолчанию карточки: название → риск/статус → количество/сумма → «Открыть расчёт».

Выбор строк: checkbox заголовка выбирает только видимую страницу; рядом явно «Выбрано 25 на этой странице». При смене фильтра выбранные скрытые строки не участвуют в операции без явного подтверждения. Для первой версии проще очищать выбор с сообщением. Не подразумевать «все 10 000».

При обновлении оставить прежние строки и метку «Обновляем…», заблокировать действия изменения до завершения. Если обновление упало, старый результат пометить устаревшим. Сортировка покрытия — по возрастанию, количества — по убыванию; одинаковые значения стабилизировать SKU + склад. Нулевой заказ остаётся доступным через фильтр, не выглядит ошибкой.

**Приёмка S01:** фильтры, счётчики и экспорт имеют однозначную область; открытие/закрытие позиции сохраняет поиск, страницу и прокрутку; бюджет не складывает неизвестную цену как 0; четыре рабочие строки видны при 1440×900 без рекламного блока.

## S02 · Карточка позиции · drawer /procurement?item=...

На desktop — правая панель 600 px поверх контекста; на телефоне полноэкранная. Заголовок: название, SKU, склад, риск и статус отдельными метками. Кнопка закрытия доступна постоянно. Основные действия в нижней панели, не перекрывающей последний элемент; учитывать safe-area-inset-bottom.

Секции:

1. **Решение:** рекомендовано / к заказу / стоимость. Разница между алгоритмом и ручным решением видна рядом.
2. **Расчёт:** спрос на срок поставки + страховой запас − остаток − учитываемый транзит = чистая потребность; далее MOQ и кратность. Данные брать с сервера. Не пересчитывать незаметно другим алгоритмом в UI.
3. **Сигнал спроса:** фактические продажи, скорректированный спрос, прогноз; периоды отсутствия выделены диапазонами, выбросы маркерами. Период и единица на графике, легенда и табличная альтернатива. Зум периода не меняет расчёт.
4. **Источники и ограничения:** период продаж, источник остатка, входящие поставки, дата среза; недоступные сведения обозначены явно.
5. **История решений [API]:** автор, время, предыдущее/новое значение, причина, версия расчёта. До появления истории — информативное отсутствие, не фиктивные сотрудники.

Редактирование: поле количества с единицей, текущая кратность, причина изменения [API]. Валидировать пустое, отрицательное, нечисловое, чрезмерное значение и кратность. Разрешённый дробный шаг приходит из единицы/правил поставщика. Не использовать автоматическое превращение пустого поля в 0. «Сохранить» показывает состояние запроса. «Утвердить» недоступно при несохранённых изменениях и объясняет причину. Серверный ответ обновляет строку и итоги.

Закрытие грязной формы: «Изменения не сохранены» → «Продолжить редактирование» / «Закрыть без сохранения». Конфликт версии [API] → показать новую серверную величину и собственную правку, предложить пересмотреть. Повторный клик не создаёт двойного действия. При переключении SKU старый график немедленно убирается; поздний ответ предыдущего запроса игнорируется.

## S03 · Данные · /data

Основная страница — реестр пяти типов источников: продажи, остатки, транзит, периоды отсутствия, поставщики. Карточка содержит источник, количество принятых/отклонённых строк, период, время импорта и статус проверки **только если это известно API**. Статус соединения не равен свежести данных.

Кнопка «Загрузить данные». Мастер [часть API]:

| Шаг | Что показывает | Условие перехода |
|---|---|---|
| Выбор | Отдельный файл или книга из 5 листов; ограничения формата/размера из сервера | Файл выбран, формат поддерживается |
| Сопоставление | Лист → тип; колонка → поле; образец 5 строк | Все обязательные поля назначены однозначно |
| Проверка | Ошибки и предупреждения по строкам, возможные дубли, единицы, даты | Блокирующие ошибки устранены либо политика частичного импорта явно разрешена |
| Подтверждение | Что заменится, что добавится, сколько строк исключится | Явное подтверждение конкретного результата |
| Результат | Принято/отклонено; затем отдельный пересчёт и ссылка на план | Сервер подтвердил импорт и расчёт |

Существующий API сразу импортирует файл: новый UI не должен изображать настоящий dry-run. До реализации preview/commit оставить простой импорт, объяснить действие до загрузки и показать фактический отчёт. Drag-and-drop — дополнение к доступной кнопке выбора файла. Ошибки остаются на экране, toast не единственный отчёт.

Встроенные demo-наборы перенести в отдельный блок «Демонстрационные данные» с объяснением замены. Новый экстремальный набор из `9fb5234` также проверять на происхождение и маркировать как тестовый сценарий, не как доказательство качества модели.

## S04 · Исключения · /exceptions

Назначение — понять влияние подозрительного события. Первая версия использует существующий список выбросов. Позже [API] добавить отсутствующую цену/срок, просроченный транзит, неизвестную единицу, конфликт справочника. Категории не смешивать в один счётчик «ошибок AI».

Список: тип, товар/склад, дата, наблюдаемое значение, обычный уровень, объяснение, влияние на расчёт. Фильтры: тип, поставщик, склад, период. При переходе в карточку позиции сохранить фильтр исключений. Клиентский идентификатор — только техническая ссылка; не выдумывать имя клиента.

Карточка: «Наблюдали 650; обычный уровень 28; событие исключено из регулярного спроса, исходная продажа сохранена». Это пример, значения брать из ответа. Ручное включение обратно — отдельная будущая функция с причиной, правами и пересчётом. Пока её нет, не рисовать активную кнопку. Телефон: вертикальные записи со всеми полями, включая полную причину; не скрывать её за горизонтальным скроллом.

## S05 · Проверка и экспорт

Диалог показывает область («выбранные 7» / «все 42 по фильтру»), число поставщиков, известный бюджет, пропущенные цены и состояния. Пользователь выбирает формат. Утверждённые и черновики явно различаются. Текущий API экспортирует все строки: пока нет scoped export, писать «Экспорт всех рекомендаций» и не обещать выгрузку выбора.

[API] Сервер возвращает экспорт для конкретного run_id и списка ID, проверяет доступ и версии. При частичном отказе не называть файл полным. В файле нужны SKU, наименование, склад, поставщик, единица, количество, цена/валюта, статус, источник расчёта. Подтверждение загрузки файла означает только экспорт, никогда отправку поставщику.

## S06 / S07 · История и политики · этап 2

История: список запусков с датой среза, источниками, параметрами и изменениями; открытие старого запуска только для чтения. Сравнение двух запусков выделяет изменение количества, риска и причины. Нужны неизменяемые снимки API.

Политики: срок покрытия, страховой запас, MOQ/кратность, правила транзита и ограничений по категориям. Каждое поле имеет единицу, допустимый диапазон, источник и область действия. Сначала предпросмотр влияния, затем сохранение новой версии. Недоступные в backend параметры не публиковать как работающую настройку. В рабочую навигацию эти разделы добавляются после реализации; в прототипе помечаются «Концепция».
