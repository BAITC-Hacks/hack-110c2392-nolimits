# Информационная архитектура и сценарии

## Навигация

| Раздел | Маршрут после внедрения | Назначение | Этап |
|---|---|---|---|
| План закупок | `/procurement` | Единая очередь рекомендаций, виды по товарам/поставщикам | 1 |
| Данные | `/data` | Наборы, дата среза, импорт, карта ошибок | 1 |
| Исключения | `/exceptions` | Крупные события, пропуски, неподтверждённые параметры | 1, часть действий API |
| История решений | `/history` | Расчёты, правки, утверждения, экспорты | 2, API |
| Политики закупки | `/policies` | Поставки, MOQ, единицы, категории, уровни сервиса | 2, API |

Не показывать неготовые маршруты как работающие пустые страницы в production. На макете они доступны для обсуждения и подписаны как концепция. В MVP существующий state-based routing допустим; прямые URL нужны перед полноценной многопользовательской работой.

Верхняя панель: рабочая область, текущий склад/охват, источник, время среза. Название страницы одно. Аватар и организация появляются только при наличии реальной идентификации. Статус API в нижней части навигации; он не заменяет свежесть набора.

## Основной сценарий закупщика

1. Открыть план. Увидеть выбранный набор, время расчёта, число строк с проблемами.
2. Открыть вид «Нужно заказать» или «Критичные». Фильтры применяются к таблице и видимым метрикам.
3. Открыть позицию без потери фильтра и прокрутки. Проверить запас, дату прихода, прогноз и округление.
4. Если данных недостаточно — перейти к конкретной проблеме. Если данные достаточны — оставить рекомендацию или ввести изменение с причиной.
5. Сохранить правку. Показать old/new, новый бюджет при известной цене, статус «Изменён».
6. Проверить пакет поставщика. Строки без количества/единиц/актуального источника не включать в утверждение.
7. Утвердить текущую версию при наличии серверной поддержки. Показать результат, не предлагать повторный клик во время запроса.
8. Экспортировать с явным составом и форматом. Сообщить «Файл подготовлен», не «Заказ отправлен».

## Импорт

`Выбор файлов → определение формата → сопоставление полей → проверка → подтверждение замены/добавления → расчёт`.

Для распознанной схемы шаг сопоставления показывается в свёрнутом подтверждённом виде. Не скрывать существенные предположения. При частичной загрузке число принято/отклонено и влияние на расчёт остаются видимыми. Не заменить рабочий набор, если проверка ещё не закончена. При отмене исходное состояние сохраняется.

Карточки источников: продажи, остатки, поставки, правила поставщика, интервалы отсутствия. Сезонность/прирост — дополнительные источники с явным статусом «не загружено / используется». Загруженный файл не равен успешно обработанному набору.

## Возврат и сохранение контекста

Фильтры и сортировка — в URL или локальном сохранённом виде, выбор строк привязан к текущему расчёту. Возврат из карточки сохраняет scroll и фокус. При изменении набора/run_id очистить выбор строк и объяснить это. Смена фильтра скрывающего выбранные строки показывает точное количество выбора либо очищает только после явного правила; предпочтение MVP — выбор только внутри текущего вида.

Несохранённая правка: закрытие карточки вызывает небольшой диалог «Изменения не сохранены» с «Остаться» и «Не сохранять». Повторный запрос не отправлять автоматически. Переход на другой товар имеет то же поведение.

## Статусы: три независимые оси

| Ось | Значения | Где показывать |
|---|---|---|
| Риск запаса | Критичный, высокий, обычный, неизвестен | Первый столбец, пояснение в карточке |
| Решение | Черновик, изменён, утверждён; экспорт как событие | Количество/действия/история |
| Данные | Достаточно для расчёта, есть допущения, недостаточно, устарели | Отдельная метка и блокеры |

Снятие риска не означает утверждение. Утверждение не исправляет качество данных. Экспорт не меняет риск и не является доставкой поставщику.

## Совместная работа (проектируемый контракт)

Два менеджера меняют одну позицию: отправлять ожидаемую версию, сервер возвращает конфликт, UI показывает новое серверное и локальное значение. Не перезаписывать последнее изменение молча. Текст: «Позицию изменил другой участник. Проверьте новую версию перед сохранением». Имя показывать только если оно действительно пришло от сервера. Это [API], текущий endpoint этого не обеспечивает.

Пересчёт создаёт новую версию плана. Предыдущие утверждения не мигрируют автоматически. До реализации версий показывать ограничение и не симулировать аудит в localStorage как промышленный журнал.
