# Совместная работа

Перед каждой новой задачей получить актуальное состояние GitHub (`git fetch origin`), проверить `git status` и изменения основной ветки. Начинать изменения на основе последней `origin/main`: для чистой ветки использовать `git merge --ff-only origin/main`; если ветки разошлись, сначала сохранить свою работу отдельным коммитом и аккуратно интегрировать изменения. Не применять `reset --hard`, `clean` или принудительную отправку для синхронизации.

В проекте работают несколько участников. Сохранять чужие незакоммиченные изменения, не включать их в свой коммит. Добавлять в индекс конкретные файлы своей задачи. Отдельно коммитить исправления приложения и материалы будущего дизайна. Перед отправкой повторить `git fetch origin`, проверить отсутствие конфликтующих изменений. Обновление кода не означает замену пользовательской базы данных демонстрационным набором.

Для изменений интерфейса проверять сборку frontend и затронутые экраны на ширинах 320, 390, 720, 768 и 1440 CSS px. На телефоне проверять навигацию, шапку, формы, таблицы, карточку товара и отсутствие горизонтальной прокрутки всей страницы; широкая рабочая таблица может прокручиваться только внутри своего контейнера.
